# DTV-tools 仕様書

## 1. 概要

動画ファイルからフレーム毎にOCR（光学文字認識）を実施し、映像中に表示されている数字を抽出・記録するデスクトップGUIアプリケーション。

---

## 3. 機能要件

### 3.1 動画読み込み

- ファイルダイアログからローカルの動画ファイルを選択・読み込みできる
- 対応フォーマット：一般的な動画フォーマット（mp4, avi, mov 等）

### 3.2 OCR対象範囲の選択

- 読み込んだ動画の任意のフレームをGUI上に表示する
- ユーザーがマウス操作で矩形領域を選択し、OCR対象範囲として指定できる
- 選択した範囲はGUI上に視覚的に表示される（赤枠）
- ツールバーの描画モード（**ROI選択** / **OCR範囲指定**）を切り替えることで、2種類の矩形を描画できる

#### 3.2.1 OCR実施範囲（サブROI）の設定

- ツールバーで「OCR範囲指定」モードを選択した状態でROI内をドラッグすると、OCR実施範囲（サブROI）を設定できる（黄枠で表示）
- OCR実施範囲はROIに対する**相対座標**で管理し、トラッキングによるROIの移動に追従する
- OCR実施範囲を設定しない場合は、トラッキングROI全体をOCR対象とする（従来動作）
- 「OCR範囲クリア」ボタンでOCR実施範囲を解除できる
- ROIを再選択した場合はOCR実施範囲も自動的にリセットされる

### 3.2.5 過去のOCR結果の読み込み

- 動画読み込み後、ツールバーの「**OCR結果を読み込む**」ボタンでファイルダイアログを開き、過去にOCR処理で生成したCSVファイルを選択できる
- 読み込み対象のCSVフォーマットは3.6節のCSV出力フォーマット（`frame`, `value` 列）と同一とする
- 読み込んだCSVの内容をGUI（フレームビューア・結果一覧リスト・OCR結果入力欄）に即時反映する
- CSVのフレーム数と読み込み済み動画のフレーム数が異なる場合は確認ダイアログを表示し、ユーザーが続行を選択した場合のみ読み込む
  - 動画フレーム数を基準とし、CSV に存在しないフレームは `None` として補完する
- 読み込み後はCSV保存ボタンが有効になり、読み込んだ結果を別名で保存できる
- 「OCR結果を読み込む」ボタンは動画を読み込むまで無効（disabled）とする

### 3.3 フレーム毎のOCR処理

- 指定したOCR対象範囲に対して、全フレームを対象にOCR処理を実行する
- 各フレームから検出された数字を記録する
- OCR結果の期待値は整数とし、末尾の `.` や数字以外の文字は除去して整数に変換する
  - 変換できない場合（検出なし・数字が含まれない）は `None` として扱う
- 処理の進捗をGUI上に表示する（プログレスバー等）
- 3.2で選択した初期矩形領域を基準に、フレーム毎にOCR対象範囲をトラッキングする
  - トラッキングアルゴリズム：TBD（例：OpenCV TrackerCSRT / TrackerKCF）
  - トラッキングに失敗したフレームは初期範囲にフォールバックする
  - GUI上の「トラッキング有効」チェックボックスでトラッキングのOn/Offを切り替えられる
    - **On**（デフォルト）：フレーム毎にROIをトラッキングしながらOCRを実行する
    - **Off**：全フレームで初期選択ROIを固定してOCRを実行する（トラッキング処理をスキップ）
  - 設定はOCR実行前に行う（実行中の変更は次回OCR実行時に反映される）

#### 3.3.1 画像前処理（OCR精度向上）

- GUI上の「**画像前処理**」チェックボックスでOCR前の画像前処理のOn/Offを切り替えられる
  - **Off**（デフォルト）：クロップ画像をそのままEasyOCRに渡す
  - **On**：グレースケール変換 → 拡大 → CLAHE → Otsu二値化のパイプラインを実施する
- 拡大処理は最短辺が200px以上になるよう整数倍スケーリングを行う  
  ただし拡大後の最大辺が **4000px** を超えないよう scale を自動制限し、メモリ不足（`cv::OutOfMemoryError`）を防ぐ
- 前処理中にOpenCVエラーが発生した場合は元画像のまま認識を継続し、フレームをスキップしない

#### 3.3.2 並列処理（OCR高速化）

- GUI上の「**並列処理（OCR高速化）**」チェックボックスでOCR並列処理のOn/Offを切り替えられる
  - **Off**（デフォルト）：全フレームを順次処理する（従来動作）
  - **On**：フレームをバッチに分割し、バッチごとにトラッキング・切り出し→OCR並列実行を繰り返す
- 並列処理時の処理フロー（バッチ単位で繰り返す）：
  1. **フェーズ1（順次）**：バッチ内フレームのトラッキング更新と画像切り出しを順番に実行する  
     ※ トラッキングは前フレームの状態に依存するため順次処理が必須
  2. **フェーズ2（並列）**：切り出したバッチ内フレームの画像に対してOCR推論をスレッド並列で実行する
- バッチサイズは `スレッド数 × 4` を基準に自動決定する（大容量動画でのメモリ使用量を抑制）
- 並列度（スレッド数）はシステムのCPU数に応じて自動決定する
- チェックボックスの設定はOCR実行前に行う（実行中の変更は次回OCR実行時に反映される）

#### 3.3.3 セグメント分割トラッキング（手振れ対策）

- GUI上の「**[案D] セグメント分割トラッキング有効**」チェックボックスで機能のOn/Offを切り替えられる
  - **Off**（デフォルト）：全フレームを1つのROIでトラッキングする（従来動作）
  - **On**：動画を指定フレーム数ごとのセグメントに分割し、各セグメント先頭でトラッカーを再初期化する
- セグメント間隔はスピンボックスで指定する（単位：フレーム数）
  - デフォルト値：180フレーム（FPS=30のとき約6秒）
  - 設定値とFPSの換算値（秒数・セグメント総数）を隣のラベルにリアルタイム表示する
- 「**セグメントROI設定...**」ボタンでセグメントROI設定ダイアログを開くことができる

##### セグメントROI設定ダイアログ

| UI要素                       | 説明                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| セグメント間隔入力＋「適用」 | ダイアログ内でも間隔を変更・反映できる                                |
| セグメント一覧（Treeview）   | 全セグメントの開始フレーム・時刻・ROI状態を一覧表示する               |
| このセグメントのROIを設定    | 選択セグメントの先頭フレームにメイン画面を移動し、ROI設定モードに入る |
| このセグメントのROIをクリア  | 選択セグメントのROI設定を削除する（直前ROI引継ぎに戻す）              |
| 全ROIクリア                  | すべてのセグメントROI設定を一括削除する                               |

- セグメントROI設定モード中はROIドラッグ時の矩形枠がシアン（`#00cccc`）で表示される
- 設定したセグメントROIは `_show_frame` にてシアン破線枠でオーバーレイ表示される
- セグメント先頭フレームでROIが未設定の場合は、直前の成功ROIを引き継いでトラッカーを再初期化する
- セグメント0（先頭）のROIはメインROI（通常ドラッグで設定）を使用する
- 設定は `src/settings/performance_settings.json` に保存・復元される
  - `segment_tracking_enabled`：機能のOn/Off（bool）
  - `segment_interval`：セグメント間隔（フレーム数、int）

- 各フレームのトラッキング結果（矩形領域の座標）を別途ファイルに保存する
  - 保存フォーマット：JSON（フレーム番号→矩形座標のマッピング）
  - 例：`{"0": {"x": 10, "y": 20, "w": 100, "h": 50}, "1": {...}, ...}`

### 3.4 結果の確認（フレームビューア）

- OCR処理終了後、GUIでフレームと対応する数字を一覧・確認できる
- フレーム送り操作（前のフレーム／次のフレームへの移動）をGUI上で行える
- 現在表示中のフレーム番号とOCR結果をGUI上に表示する
- 各フレームで保存されたトラッキング範囲（矩形領域）をフレーム上にオーバーレイ表示する
- トラッキング範囲の表示／非表示を切り替えられる

### 3.5 OCR結果の編集

- GUI上で各フレームに対応するOCR結果（数字）を手動で編集できる
- 編集は即時反映され、保存前に内容を確認できる

### 3.6 CSV出力

- 最終的なフレーム番号と数値の組み合わせをCSVファイルとして保存できる
- 保存先はファイルダイアログで指定できる
- CSVフォーマット：

  ```
  frame,value
  0,123
  1,456
  ...
  ```

### 3.7 解析・統計タブ

アプリに **解析・統計** タブを追加し、OCR結果とGPS/時刻ログCSVを突き合わせてマップ表示・出力を行う。

#### 3.7.1 タブ構成

| UI要素            | 説明                                                  |
| ----------------- | ----------------------------------------------------- |
| CSV読み込みボタン | ファイルダイアログからGPS/時刻ログCSVを選択・読み込む |
| 解析ボタン        | 読み込んだCSVとOCR結果を突き合わせて解析を実行する    |
| 出力ボタン        | 解析結果（CSV・マップ画像）をファイルに出力する       |

#### 3.7.2 入力CSVフォーマット

- 対象ファイル例：`data/sample.csv`
- 必須カラム：`lat`（緯度）、`lon`（経度）、`timestamp`（Unixタイムスタンプ、秒）
- その他のカラムはそのまま保持して出力に引き継ぐ

```
id,lat,lon,timestamp
1,35.041764,137.168128,1780013208
2,35.041776,137.168170,1780013209
...
```

#### 3.7.3 タイムスタンプとOCR結果のリンク

- 動画の先頭フレームに対応するUnixタイムスタンプをユーザーが入力 or 設定ファイルで指定する
- 各フレームの時刻 = `動画開始タイムスタンプ + フレーム番号 ÷ FPS`
- CSVの各行（`timestamp`）に対し、同一秒内（`timestamp` 以上 `timestamp + 1` 未満）に相当するフレームをすべて収集する
- 収集したフレームのOCR結果のうち、**最も出現頻度の高い値**をその行のOCR結果として採用する
  - `None`（検出なし）は頻度集計から除外する
  - 候補が存在しない場合は `None` とする

#### 3.7.4 マッピング・マップ表示

- `lat` / `lon` カラムの座標をプロット点としてマップ上に配置する
- 隣接する点を順番に線で結び、走行ルートを可視化する
- 各線分（区間）の色は、始点行のOCR採用結果に基づいて色分けする

##### GUI内マップ表示

GUIのマップ表示エリアには2種類の表示モードを提供する。

| モード                 | 内容                                                                          |
| ---------------------- | ----------------------------------------------------------------------------- |
| 通常表示（デフォルト） | matplotlib による簡易ルートプレビュー（緯度・経度軸）                         |
| 地図タイル表示         | contextily によりOpenStreetMapタイルを背景に重ねた地図上のルート表示（GUI内） |

- 「**地図タイル表示 (OpenStreetMap)**」チェックボックスで2モードを切り替える
  - チェックON：OSMタイルを背景として取得し、実際の地図上にルートを描画する
  - チェックOFF（デフォルト）：タイルなしのmatplotlib単純プレビューを表示する
  - タイル取得にはインターネット接続が必要。オフライン時は通常プレビューに自動フォールバックする
- チェックボックスの切り替えは解析実行後いつでも行え、即座にマップが再描画される

##### ブラウザ表示

- 「**ブラウザで地図を開く**」ボタンを押すと、folium で生成したインタラクティブHTMLマップをデフォルトブラウザで開く
  - OpenStreetMap タイルを背景に使用し、実際の地理情報上にルートをオーバーレイ表示する
  - 各地点にはサークルマーカーを配置し、クリックするとポップアップで緯度・経度・OCR結果を確認できる
  - ルートは始点行のOCR結果に応じた色の `PolyLine` で描画する
- 「ブラウザで地図を開く」ボタンは解析実行後に有効化される

##### 色設定ファイル

- JSON形式の外部ファイルで結果と色の対応を定義する
- **デフォルト設定ファイル：`src/settings/color_settings.json`**
  - アプリ起動時に自動的に読み込まれ、GUIラベルに「`color_settings.json`（デフォルト）」と表示される
  - ファイルが存在しない・読み込めない場合はグレー（`#888888`）のみを使用する
- GUIの「色設定ファイルを開く」ボタンで別のファイルを選択するとデフォルト設定を上書きできる
- フォーマット：

  ```json
  {
    "80":  "#00AA00",
    "60":  "#FFAA00",
    "40":  "#FF0000",
    "Other": "#888888"
  }
  ```

  - キーはOCR結果の文字列（整数値を文字列として記述）
  - 設定に存在しない結果は `"Other"` キーの色を使用する
  - `"Other"` キーが未定義の場合はグレー（`#888888`）をデフォルトとする

#### 3.7.5 出力

出力ボタンを押すと以下のファイルを保存先ディレクトリに出力する。

| ファイル     | 内容                                                         |
| ------------ | ------------------------------------------------------------ |
| `result.csv` | 入力CSVの全カラムに `ocr_result` カラムを追加したCSV         |
| `map.png`    | matplotlib によるルートマップのスクリーンショット（PNG形式） |
| `map.html`   | folium によるインタラクティブHTMLマップ                      |

- `result.csv` の追加カラム：

  ```
  id,lat,lon,timestamp,ocr_result
  1,35.041764,137.168128,1780013208,80
  2,35.041776,137.168170,1780013209,80
  ...
  ```

- 保存先はファイルダイアログで指定できる

## 4. 非機能要件

- GUIは直感的に操作できるシンプルなレイアウトとする
- OCR処理中はUIがフリーズしないよう、バックグラウンド処理（スレッド等）で実行する
- 並列処理有効時は `ThreadPoolExecutor` によりOCR推論を複数スレッドで同時実行し、処理速度を向上させる
